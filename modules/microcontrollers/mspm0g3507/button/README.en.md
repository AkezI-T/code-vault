# button

[简体中文](README.md) | English

A nonblocking single-button state machine emitting delayed short-click, double-click and one-shot long-press events. The caller supplies level and time, using application GPIO sampling on MSPM0G3507 or another C input source. No DriverLib dependency, global state or heap allocation.

## Environment and configuration

C99 C API; C++ callers must include the header inside extern "C". Compile the [source](src/msp_button.c) and add the directory containing the [header](include/msp_button.h). The GPIO example uses MSPM0 SDK 2.09.00.01 DriverLib, SysConfig and TI Arm Clang 4.0.4.LTS. The state machine itself only needs stdbool.h/stdint.h.

Create GPIO group BUTTON, input INPUT, generating BUTTON_PORT/BUTTON_INPUT_PIN in SysConfig. Select an actual pin. The active-low example uses a pull-up and switch to ground; active-high wiring needs matching pull-down and levels. Stay within MCU voltage limits. After SYSCFG_DL_init, initialize the state machine and sample approximately every 1 ms. Pass true for physical high level. The example exclusively owns SysTick as a 1 ms clock; use an existing continuous millisecond counter with an RTOS/timebase.

| Type/field | Unit, range, default and meaning |
| --- | --- |
| MSP_BUTTON_CONFIG_DEFAULT | MspButtonConfig initializer: active low, 20 ms debounce, 700 ms long press, 500 ms double-click gap. |
| MspButtonConfig.active_high | bool; true=active high, false=active low, default false. |
| MspButtonConfig.debounce_ms | uint16_t, 1..65535 ms; first-press confirmation and second-press inspection delay, default 20. |
| MspButtonConfig.long_press_ms | uint16_t, debounce_ms..65535 ms; long-press threshold, default 700. |
| MspButtonConfig.double_gap_ms | uint16_t, 1..65535 ms; interval from first release to pending short-click expiry, default 500. |
| MspButton.config | Internal configuration copy; do not modify after init. |
| MspButton.state | uint8_t internal phase, not a public enum; managed by init/scan. |
| MspButton.press_ms | uint32_t internal long-press start timestamp, milliseconds. |
| MspButton.release_ms | uint32_t internal first-release timestamp, milliseconds. |
| MspButton.debounce_ms | uint32_t internal debounce-start timestamp, milliseconds; distinct from the same-named configuration duration. |
| MspButtonEvent | Enum: MSP_BUTTON_EVENT_NONE=no event; MSP_BUTTON_EVENT_SHORT=short click; MSP_BUTTON_EVENT_DOUBLE=double click; MSP_BUTTON_EVENT_LONG=long press. |

## Complete minimal example

GPIO names and CPUCLK_FREQ are generated by application SysConfig; adjust names and clocks to the application. last_event represents the latest event delivered to application logic.


```c
#include "ti_msp_dl_config.h"
#include "msp_button.h"

static MspButton button;
static volatile uint32_t ticks_ms;
static volatile MspButtonEvent last_event;

void SysTick_Handler(void) { ++ticks_ms; }

int main(void)
{
    SYSCFG_DL_init();
    const MspButtonConfig config = MSP_BUTTON_CONFIG_DEFAULT;
    if (!msp_button_init(&button, &config, 0U) ||
        SysTick_Config(CPUCLK_FREQ / 1000U) != 0U) {
        for (;;) {}
    }
    uint32_t previous = ticks_ms;
    for (;;) {
        uint32_t now = ticks_ms;
        if (now != previous) {
            previous = now;
            bool high = DL_GPIO_readPins(BUTTON_PORT, BUTTON_INPUT_PIN) != 0U;
            MspButtonEvent event = msp_button_scan(&button, high, now);
            if (event != MSP_BUTTON_EVENT_NONE) last_event = event;
        }
    }
}
```

## API


```c
bool msp_button_init(MspButton *button, const MspButtonConfig *config, uint32_t now_ms);
MspButtonEvent msp_button_scan(MspButton *button, bool level_high, uint32_t now_ms);
```

msp_button_init takes non-NULL writable button storage, non-NULL input config, and uint32_t now_ms in milliseconds at initialization. Copies config, sets all three timestamps to now_ms and selects released state; returns true on success. NULL pointers, debounce_ms=0, long_press_ms<debounce_ms or double_gap_ms=0 return false without modification. No prior zero initialization is needed. Reinitialization discards the current gesture. The example shows default initialization.

msp_button_scan requires a successfully initialized, non-NULL button. level_high is the sampled physical level (true=high, false=low); do not pre-invert it for polarity. now_ms is monotonic uint32_t milliseconds, allowing modulo-2^32 wrap, with call gaps below 2^31 ms. Returns a MspButtonEvent with at most one event per call, NONE when no event occurs. There is no error enum or NULL check; the application must meet these preconditions. The example shows sampling and event handling in a task loop.

## Exact gesture semantics and limits

First observed press starts debounce. At the threshold, only that sample must still be pressed; continuous stability throughout the interval is not required. The first long-press duration starts after debounce confirmation. First release immediately starts double_gap without release debounce. SHORT occurs only when still released at gap expiry. Press is checked before gap expiry, so a sparsely sampled press observed on an expired-gap call still enters the second-press phase.

Second press starts debounce and long-press timing together at its first observed press. After debounce, an observed release immediately emits DOUBLE; an earlier intervening release does not restart that delay. Holding the second press until long_press emits LONG and consumes the pending first short click. Both first and second long presses emit once and rearm after release. Release has priority over the long threshold. There is no release debounce or repeating long-press event.

Every call returns immediately, sleeps nowhere and accesses no hardware. Different instances are independent. Use a single main-loop/task context serially per instance; concurrent task/ISR access is unsupported. No internal interrupt masking is needed or provided. Supply a stable timebase and adequate sampling rate; event precision is limited by sampling and missed edges are not reconstructed. Keep storage valid while scanning. No asynchronous buffers, allocation or cleanup API; release storage after stopping calls.
